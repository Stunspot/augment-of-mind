# Hesperos authoring evidence packet

## Assignment

Author and materially revise the complete MIND `1.0.0` customer journey and
GitHub Pages source. The optional Core remains version `0.2.0`. The work must
serve installation, first value, ordinary use, recovery, capability and host
boundaries, privacy, security, support, terms, package inspection, and release
orientation without promoting construction evidence beyond its earned state.

The release brief also requires three inspected visual roles:

- square product icon, `1024 x 1024` (`1:1`);
- landscape hero, `1600 x 900` (`16:9`);
- portrait capability card, `1080 x 1350` (`4:5`).

## Reader model

The primary reader can operate Codex and add a plugin marketplace but is not
assumed to understand plugin manifests, component versioning, H0/H1 delivery
evidence, Python wheels, or the distinction between installation, discovery,
invocation, and healthy behavior.

The documentation therefore begins with a choice of task, gives one complete
Codex path, supplies observable outcomes and stopping states, then opens deeper
component and evidence detail only when the reader asks for it.

## Claims allowed by the source

- The plugin contains one MIND integrator and fifteen Faculty skills.
- Nova is neither included nor required.
- The plugin is skills-only and does not install or start optional Core.
- Core `0.2.0` provides a local SQLite metadata foundation and explicit H0
  associative-reminder queries.
- The reminder field is an unordered semantic neighborhood, not a universal
  tool-fitness scalar, top-K recommendation, capability selection, activation,
  health claim, permission grant, or action authority.
- Current public Codex support is H0/query-capable. Construction of a portable
  delivery envelope and a separately tested Exoframe seam does not establish a
  complete live H1 or provider-receipt claim.
- The customer archive is one positive-allowlist ZIP with one versioned root
  and an optional offline-installable Core wheel.

## Claims deliberately withheld

- automatic pre-turn Core delivery in Codex;
- public-directory publication;
- Claude distribution or live Claude behavior;
- automatic capability inventory, embeddings, tool choice, or invocation;
- a bundled private capability estate;
- provider receipt, model attention, or downstream-use proof;
- accessibility conformance before scoped live review;
- support response times, hosted service, warranty, or professional advice.

## Authored surface

`documentation-manifest.json` is the canonical authored-file list for this
run. It contains 18 customer files: the repository README, 15 task-oriented
root documents, and the HTML/CSS Pages source. The separately governed
`LICENSE.md` is shipped and linked but is not laundered into a Hesperos
authorship claim. The exact authored byte set is bound by the receipt.

## Validation boundary

Local validation covers document structure, Markdown accessibility heuristics,
link resolution, Pages structure, image roles and dimensions, source tests,
and exact authorship bytes. The in-app browser refused a local `file://` URL by
policy. No alternate URL or browser route was used to disguise that blocked
operation. Rendered, responsive, keyboard, and live-link evidence therefore
remains a post-deployment Pages gate.
